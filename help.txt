# 🚀 forge - AI Coding Agent Documentation

## Overview
forge is a terminal-based AI coding agent that helps automate codebase exploration, file editing, and task execution! 🎯 Think of it as a developer assistant that can read code, create new files, modify existing ones, and run tests - all through natural language commands. ✨

## Project Structure
- `./agent/` - Core AI agent implementation (`loop.py`, `llm.py`, `prompts.py`, `memory.py`) 🤖
- `./sandbox/` - Safe execution environment (`docker_runner.py`) 🐳
- `./tests/` - Automated testing framework (`test_tools.py`) 🧪
- `./tools/` - Utility functions (`read_file.py`, `codebase.py`, `write_file.py`) 🛠️
- `./main.py` - Entry point and command dispatcher ⚡
- `./build-your-own-ai-coding-agent.md` - Complete technical documentation 📖
- `./.env` - Environment variable configuration 🔧
- `./requirements.txt` - Python dependency list 📦
- `./pyrightconfig.json` - Type checking configuration ✅
- `./README.md` - Project readme and quickstart guide 📝

## Key Components
1. **AI Agent Loop** (`agent/loop.py`) 🔄
   - Manages conversation history and tool usage
   - Implements ReAct pattern for tool-assisted reasoning
   - Handles context window management
   - Supports multi-turn conversation with memory persistence 👼

2. **Language Model Integration** (`agent/llm.py`) 🧠
   - Provides LLM API abstraction layer
   - Handles prompt formatting and response parsing
   - Supports configurable model parameters (temperature, max tokens, etc.)

3. **Prompt Engineering** (`agent/prompts.py`) 💬
   - System prompt templates for various agent behaviors
   - Context-aware prompt construction
   - Tool-use instruction templates

4. **Memory System** (`agent/memory.py`) 💾
   - Conversation history storage and retrieval
   - Context pruning to manage token limits
   - Persistent session state across runs

5. **Execution Environment** (`sandbox/docker_runner.py`) 🏗️
   - Isolated execution context for code modifications
   - Prevents accidental file corruption outside project scope
   - Supports sandboxed testing of generated code

6. **File Operations** (`tools/`) 📂
   - `read_file.py` - Safe file reading with line-range selection and encoding handling
   - `write_file.py` - Controlled file writing/modification with validation
   - `codebase.py` - Comprehensive codebase navigation utilities (search, tree, analyze) 🔍
   - `tools.py` - Tool registry and dispatch system

## Usage Guide

### Starting the Agent
```bash
python main.py
```

### Available Commands 🎮
- **Code Exploration**: "Find all functions related to authentication" 🔎
- **File Creation**: "Create a new test for this module" 📝
- **Bug Fixing**: "Fix the bug in utils.py" 🐛
- **Code Review**: "Review the changes in this PR" 👀
- **Refactoring**: "Refactor this function to improve readability" 🧹
- **Testing**: "Run the test suite and report failures" ✅
- **Documentation**: "Generate documentation for the API module" 📝

### Configuration ⚙️
1. **Environment Variables**: Configure via `.env` file
   - `LLM_API_KEY` - Your language model API key 🔐
   - `LLM_MODEL` - Model selection (e.g., `gpt-4`, `claude-3`) 🤖
   - `SANDBOX_ENABLED` - Enable/disable sandboxed execution 🐳
   - `MAX_CONTEXT_TOKENS` - Maximum context window size 📏
2. **Sandbox Mode**: Toggle sandboxed execution for safe code running
3. **Context Window**: Adjust context size to balance thoroughness vs. token usage
4. **Dependencies**: Install required packages via `pip install -r requirements.txt`

### Workflow Best Practices 🌟
1. **Start Simple**: Begin with focused, well-defined tasks 🎯
2. **Iterate**: Break complex tasks into smaller, verifiable steps 📊
3. **Review Changes**: Always inspect modifications before applying 👁️
4. **Use Sandbox**: Enable sandbox mode for risky or experimental operations 🛡️
5. **Test Thoroughly**: Run test cycles after any code modification 🧪
6. **Manage Context**: Monitor token usage for long sessions; clear memory when needed 🧹
7. **Validate Outputs**: Verify tool results match expectations before proceeding ✔️

### Error Handling 🚨
- If a tool call fails, the agent will retry or suggest alternatives 💪
- File read/write operations validate paths to prevent unauthorized access 🔒
- Sandbox execution isolates potentially unsafe code runs 🏢
- Check `.env` configuration if authentication or model errors occur 🔧

## Best Practices Summary 📋
- Always review changes before applying them ✅
- Use sandbox mode for risky or untested operations 🛡️
- Break complex tasks into smaller, manageable steps 🧩
- Use test cycles to verify correctness after modifications 🔍
- Keep the context window size appropriate for the task complexity 📏
- Store sensitive configuration in `.env`, never in source code 🔐
- Regularly update dependencies in `requirements.txt` 🔄

## Troubleshooting 🆘
| Issue | Solution |
|---|---|
| Agent not responding 🤐 | Check `.env` for valid `LLM_API_KEY` 🔑 |
| Sandbox errors 🐳 | Ensure Docker is running and sandbox is enabled |
| File not found 📁 | Verify file paths are relative to project root |
| High token usage 📈 | Reduce `MAX_CONTEXT_TOKENS` or break tasks into smaller steps |
| Test failures ❌ | Review test output, fix issues in source, re-run tests |

For detailed implementation guidance, refer to `build-your-own-ai-coding-agent.md`. 📚
